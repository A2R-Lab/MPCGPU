01 / THE METHOD

Structure is the advantage.

Exploit the block-tridiagonal structure of trajectory optimization, from system assembly to the final update.

01

Assemble in parallel

Build the Schur system and its structured preconditioner across the trajectory horizon.

02

Solve cooperatively

GBD-PCG distributes block rows across a cooperative CUDA grid, sharing work through synchronized iterations.

03

Update the trajectory

Evaluate candidate steps in parallel, apply the selected update, and warm-start the next control step.

02 / PUBLISHED RESEARCH

A solver designed
for longer horizons.

The paper evaluates GPU-accelerated PCG against CPU QDLDL inside nonlinear MPC, using simulated Kuka iiwa tracking tasks.

Its study reports up to 3.6× average linear-system speedup in the horizon sweep and kilohertz control rates with horizons as long as 512 knot points.

Read the methodology and complete results ↗
Published results, not a new benchmark.

RTX 4090 · Intel i9-12900K · CUDA 12.1. The study uses 100 ten-second, five-goal trials. Linear-system latency is not whole-controller latency. Updated-software timing is pending a dedicated measurement window.

04 / GET STARTED

From checkout
to a first solve.

Start with the development quickstart for dependency setup, CUDA architecture selection, and a correctness-only tracking example.

Open the quickstart ↗
MPCGPU / development checkout
git clone --recurse-submodules \
  --branch modernize-grid-glass \
  https://github.com/A2R-Lab/MPCGPU.git
cd MPCGPU
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
make build_qdldl
make examples ARCH=sm_120
LD_LIBRARY_PATH="$PWD/qdldl/build/out" \
  ./examples/pcg.exe

Choose the architecture for your GPU. CUDA cooperative-launch support is required. Branch links become main links when the corresponding changes land.
